# Панель керування — Krakow Insiders

Редагування турів і відгуків без бази даних. Панель пише вміст у JSON, сайт
читає той самий JSON — усе, що змінюється, змінюється в одному місці.

Адреса: `https://ваш-домен/admin/`

## Що потрібно від хостингу

Сайт розрахований на Vercel. Сховищем для всього, що редагує панель, є
**сам репозиторій** — окрема гілка `panel-data`. Кожне збереження стає
комітом, тож історія цієї гілки і є історія змін вмісту, а невдалу правку
можна відкотити через git.

Гілка навмисно не `main`: інакше кожне «Зберегти» запускало б збірку сайту,
і зміна з'являлася б через хвилину. Ба більше — кожен відгук від відвідувача
теж ставав би деплоєм, тобто будь-хто зміг би витрачати вашу квоту збірок.
На окремій гілці нічого не збирається, а зміни діють одразу.

Що треба зробити один раз:

1. **Зробіть репозиторій приватним.** У `panel-data` лежить `config.json` із
   хешем пароля панелі, а також фото, які надсилають відвідувачі. GitHub →
   Settings → General → Danger Zone → Change visibility. Vercel від цього не
   ламається: інтеграція вже має доступ.
2. **Створіть токен.** GitHub → Settings → Developer settings → Personal
   access tokens → **Fine-grained tokens** → Generate new token.
   - Repository access: тільки `krakow-insiders`
   - Permissions → Repository permissions → **Contents: Read and write**
   - Термін дії на свій розсуд; коли мине, панель перестане зберігати і
     треба буде видати новий
3. **Покладіть його у Vercel.** Settings → Environment Variables →
   `GITHUB_TOKEN` = виданий токен. Власника й назву репозиторію Vercel
   підставляє сам, окремо вказувати не треба.
4. **Redeploy.** Змінні оточення потрапляють у функції лише при новому
   деплої.

Поки токена немає, панель працює, але зверху світиться попередження:
збережене зникне після наступного деплою.

### Необов'язково: Vercel Blob для великого відео

Файл, який іде через функцію Vercel, не може бути більшим за 4.5 МБ — це
обмеження платформи. Фото панель стискає в браузері, тож воно вміщається
завжди, а от відео більше за ~4 МБ так не завантажити.

Якщо треба вантажити довгі ролики, підключіть Vercel Blob (Storage → Create
Database → Blob → Connect Project). Панель сама помітить
`BLOB_READ_WRITE_TOKEN` і почне відправляти файли з браузера просто у
сховище, повз функцію — ліміт підніметься до 300 МБ. Без Blob у поле відео
можна вставити посилання.

### Заявки й сповіщення в Telegram

`TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID` у тих самих Environment Variables
вмикають бота: у чат падають і заявки з форм бронювання, і нові відгуки з
посиланням на панель. Без них сайт працює, просто мовчить.

## Перший запуск

1. Задеплойте сайт і виконайте кроки вище.
2. Одразу відкрийте `https://ваш-домен/admin/`.
3. Придумайте пароль (мінімум 10 символів) — він збережеться хешем (scrypt)
   у `config.json` на гілці `panel-data`.

**Крок 3 зробіть одразу.** Доки пароль не встановлено, форму створення
пароля бачить будь-хто, хто знає адресу.

Забули пароль — видаліть `config.json` із гілки `panel-data` через веб-
інтерфейс GitHub і повторіть крок 2.

Після п'яти невдалих спроб входу панель замикається на 15 хвилин.


## Що можна редагувати

**Тури** — блок «Popular Tours» на головній. Фото, ціна, мітка, назва й опис
двома мовами. Порядок карток у панелі — це порядок на сайті. Той самий список
живить випадне меню «Tours» у формах бронювання, тож доданий тур одразу можна
забронювати через форму.

Остання картка — «на замовлення»: без фото й ціни, веде просто у WhatsApp.
Її можна сховати чи видалити, як і будь-яку іншу.

**Відгуки** — блок «What Travelers Say», дві вкладки:

- *Відео* — фото на плитці плюс відео, яке програється просто в ній.
- *Текстові* — ім'я з країною, дата, оцінка й текст двома мовами.

**Нові** — те, що надіслали відвідувачі через кнопку «Leave a review» на
сайті. Поки ви не підтвердите відгук, його не бачить ніхто, крім вас.

Кнопка «Сховати» знімає запис із сайту, не видаляючи його.

## Дві мови

Кожен текст має англійську й польську версію, які стоять поруч у редакторі.
Англійська — основна: якщо польське поле порожнє, на польській версії сайту
покажеться англійський текст. Тобто незаповнена польська нічого не ламає, але
й нічого не перекладає.

## Завантаження фото й відео

Кнопка **Вибрати файл** у будь-якому полі із зображенням або відео.

Фото стискається просто в браузері до 2560 px по довшій стороні, перш ніж
кудись піти. Це не лише про ліміти: сайт усе одно не показує знімок у
повному розмірі, тож 8 МБ із телефона перетворюються на кількасот кілобайт
без видимої різниці.

| | Формати | Максимум |
|---|---|---|
| Фото | JPG, PNG, WebP | 4 МБ після стиснення (фактично не досягається) |
| Відео | MP4, WebM, MOV | 4 МБ, або 300 МБ якщо підключено Blob |
| Фото у відгуку відвідувача | JPG, PNG, WebP | те саме |
| Відео у відгуку відвідувача | MP4, WebM, MOV | те саме |

SVG не приймається свідомо — він може містити код. Замість завантаження
можна вставити пряме посилання у поле під кнопкою; для довгого відео без
підключеного Blob це єдиний шлях.

Завантажені файли лежать у `media/` на гілці `panel-data` і віддаються через
адресу виду `/m/назва-файлу.jpg`. Оскільки в назві є випадковий хвіст, файл
ніколи не перезаписується — тому він кешується назавжди й GitHub запитується
приблизно раз на файл.

Файли від відвідувачів мають префікс `reviews-`, щоб їх було видно окремо.

## Збереження

Правки турів і відгуків накопичуються на сторінці й ідуть на сайт одним
натисканням **Зберегти** (або `Cmd/Ctrl + S`). Доки ви не зберегли, на сайті
нічого не змінилося.

Підтвердження відгуку з черги — виняток: воно зберігається одразу, окремою
кнопкою користуватися не треба. Тому, якщо у вас є незбережені правки, панель
попросить спершу зберегти їх — інакше вони загубилися б.

**Повернути початковий вміст** у меню «⋯» відновлює тури й відгуки, з якими
сайт було зібрано (`data/content.json`). Усе, що ви додали чи змінили, при
цьому зникне.

## Як влаштовано зсередини

| Файл | Що робить |
|---|---|
| `data/content.json` | Початковий вміст, який іде з репозиторієм. Використовується, доки в сховищі нічого немає, і при відновленні. |
| `api/content.js` | Віддає сайтові те, що видно відвідувачам. |
| `api/admin.js` | Усі дії панелі: вхід, завантаження, збереження, модерація. |
| `api/upload.js` | Видає браузеру короткоживучий токен на завантаження файлу. |
| `api/review-submit.js` | Приймає відгук із форми на сайті у чергу модерації. |
| `js/content.js` | Малює картки турів і відгуків на сайті з отриманого JSON. |
| `api/_lib/github.js` | Читає й пише файли на гілці `panel-data` через GitHub API. |
| `api/media.js` | Віддає завантажені файли за адресою `/m/…`. |
| `api/_lib/telegram.js` | Надсилає заявки й нові відгуки в Telegram. |

Сайт малює тури й відгуки на боці браузера. Це означає, що вміст, який
редагується, не лежить у початковому HTML: пошукові системи бачать його вже
після виконання JavaScript. Решта сторінки — заголовки, описи послуг,
трансфери, FAQ, контакти — лишилася у HTML як була.

## Локальний запуск

Без `GITHUB_TOKEN` панель сама переходить у локальний режим: JSON пише у теку
`.local-store/`, а завантажені файли — в `images/uploads/`. Обидві теки в
`.gitignore` і на сервері не існують. Так можна перевірити геть усе, зокрема
завантаження файлів, не чіпаючи ні репозиторій, ні бойовий сайт.
